# 需求

## 产品范围

- 项目只需要 Web 前端，不需要 Android 或其他客户端。
- 前端内嵌到 Go 后端中，不需要独立部署。
- 不使用 Connect RPC，只使用 `github.com/coder/websocket`。
- 前端直接通过 `/ws` 相对路径连接后端，不需要 `direct`、`relay`，也不需要一个前端连接多个后端。
- 第一版不需要文件变更列表、Git 等额外功能。
- 部分技术实现可以参考 `/workspace/project/paseo`。

## 参考与风格

- 前端设计、配色、样式参考 `/workspace/project/paseo`，以 paseo 为主。
- 可以访问 `app.paseo.sh`，输入 `localhost:6767`，体验 paseo 的前端交互。
- 同时参考 `ui-ux-pro-max`。
- 聊天页的 Tab 参考 `https://ui.shadcn.com/docs/components/base/tabs`。
- 尽量改造为 shadcn 组件。
- 文案尽量简约。

## Project 管理

- 支持 Project 列表的增删改查。
- 新建 Project 时不需要输入 Project 的 `name`。
- 侧边栏只显示 Project 路径最后一个文件夹的名字。
- 新建 Project 后自动打开一个聊天页。
- 选中 Project 后，可以新建多个聊天页。
- 顶端显示当前 Project 的完整路径和 Git 信息。
- Git 信息和 Project 完整路径显示在同一行。
- 左下角显示连接状态、后端机器名、添加 Project 和设置入口。

## 聊天页

- 每个聊天页是一个 Tab。
- 每个 Tab 占据完整高度。
- 最右侧 Tab 的右边有加号图标，用于新建聊天页。
- 没有聊天内容时，可以在聊天框下方选择 Agent、模型和思考深度。
- 每个聊天框第一次选择 Agent 后，后续聊天不能更换 Agent。
- 聊过一次以后，仍然可以更换模型和思考深度。
- 模型选择和思考深度设置都放在聊天框下面。
- 聊天框中的 Agent、模型和思考深度选择样式参考 paseo，保持简洁美观。
- 聊天框不显示“Agent”标签和“已锁定”文字。
- 用户输入文字后，才在右下角显示发送图标。
- 聊天页任务栏固定在页面最下面。
- 右上角不显示当前 Agent。
- 没有消息时不显示“还没有消息”空状态。
- AI 回复尝试使用 Markdown 渲染。
- 用户第一次输入 Prompt 时，后端初始化一个 Agent 进程，并把 Prompt 传给 Agent。
- 后端需要流式转发 Agent 的返回结果给前端。
- Agent 正在输出时，发送按钮变成停止按钮。
- Agent 输出完成后，停止按钮重新变成发送按钮。
- 用户可以主动点击停止按钮停止 Agent 输出。
- Agent 输出完成或用户停止后，用户可以继续输入 Prompt。
- 用户也可以在不点击停止的情况下直接输入并回车，行为等同于先停止当前输出，再发送新的消息。
- 输出和工具调用需要像 paseo 一样按发生顺序交替显示。
- 不允许把所有输出集中在最上面、所有工具调用集中在下面。

## 后端状态

- 所有状态由后端维护。
- 即使关闭前端网页，会话仍然继续。
- 重新打开前端网页后，仍然能看到后端继续把 Agent 输出流式返回给前端。
- 报错时需要把错误信息返回到前端。

## Agent 类型

- Agent 分为四类：
  - Claude Code。
  - Codex。
  - Mock Claude Code。
  - Mock Codex。
- Mock Agent 必须跑通：
  - Mock Claude Code 要实际调用 `claude`，但请求打到后端 Mock Claude 模型服务。
  - Mock Codex 要实际调用 `codex`，但请求打到后端 Mock Codex 模型服务。
- E2E 中不要使用真实的 Codex 和 Claude Code。
- E2E 中需要有 Mock Codex 和 Mock Claude，二者各自指向服务端 Mock 模型服务。
- 后端需要提供 Anthropic 兼容的 Mock 服务，便于测试 Claude Code。
- Claude Code 启动命令为 `IS_SANDBOX=1 claude --dangerously-skip-permissions`。
- Codex 启动命令为 `codex --dangerously-bypass-approvals-and-sandbox`。
- 启动 Claude Code 时传入 `ANTHROPIC_BASE_URL` 和 `ANTHROPIC_MODEL` 参数。
- 读取 `ANTHROPIC_MODEL` 环境变量；如果不为空，则作为 Claude 的默认模型选项。
- Codex 需要真实可用，并支持选择 `gpt-5.5`。
- Codex 使用 `gpt-5.5` 时需要支持思考深度选择：
  - Low：Fast responses with lighter reasoning。
  - Medium：Balances speed and reasoning depth for everyday tasks，默认值。
  - High：Greater reasoning depth for complex problems。
  - Extra high：Extra high reasoning depth for complex problems。
- 需要跑通 Codex 当前拿不到返回结果的问题。

## Agent 设置页

- 添加 Agent 设置页。
- 允许在 Claude Code 模型选项列表中添加新的模型项。
- 支持选择 Mock、Codex、Claude Code 等 Agent。
- 支持模型选择。
- 支持思考深度设置。

## 工具调用显示

- 实现工具调用显示。
- 工具执行结果默认折叠。
- 每个工具调用都要在标题显示具体命令，保证不展开也能知道工具调用做了什么。

## 测试要求

- 如果可以通过 `go-task e2e` 运行测试，且需要修改代码：
  - 先在测试用例中覆盖新增需求。
  - 运行 `go-task e2e -- --case <name>`，预期新增用例失败。
  - 修改代码后继续运行 `go-task e2e -- --case <name>`，直到成功。
  - 成功后运行 `go-task e2e` 执行全部测试。
- 密钥文件必须放在 `.env` 中，并且代码中主动加载 `.env`。
- 不应该放入 VCS 的文件需要通过 `.gitignore` 排除。

## 技术约束

- 前端使用 TypeScript 编写。
- 如果没有特殊声明，其他代码和脚本使用 Go 编写。
- 如果需要 Playwright，使用 `https://github.com/playwright-community/playwright-go`。
- 如果需要 Go WebSocket，使用 `https://github.com/coder/websocket`。
- 如果使用 zerolog，使用 `log.Ctx(ctx)` 打印日志，并确保日志能快速定位问题。
- 单个代码文件过大时，尝试拆分为多个文件或多个模块。
