# 开发

## 技术栈

- 后端：Go、`github.com/coder/websocket`、zerolog。
- 前端：React、TypeScript、Vite、Tailwind CSS、Lucide React。
- E2E：Go、playwright-go、Chromium。
- 任务运行：go-task。

## 环境准备

Taskfile 会主动加载仓库根目录下的 `.env`。密钥和本地私有配置应放在 `.env` 中，不要提交到 VCS。

首次运行 E2E 前安装浏览器依赖：

```bash
go-task e2e:install
```

## 本地启动

构建前端和后端后运行本地 Web 服务：

```bash
go-task run:web
```

服务默认监听 `17375` 端口，可用 `AGENTHUB_PORT` 或 `--port` 修改。CLI 参数通过 `--` 传给服务：

```bash
AGENTHUB_PORT=18080 go-task run:web
go-task run:web -- --port 18080
```

如果 `.env` 中配置了非空 `AGENTHUB_TOKEN`，或启动时传入 `--token`，前端需要输入相同 token 才能连接 WebSocket；CLI 参数优先于环境变量。

运行前端开发服务器：

```bash
go-task fe:dev
```

前端开发服务器会把 `/ws`、`/healthz` 和 `/auth` 代理到本机 `17375` 端口的 Go 后端。

## 构建

构建前端静态资源，并打包到 Go 后端二进制中：

```bash
go-task build:web
```

构建产物位于 `data/web/web`。

## 测试

运行单元测试：

```bash
go-task test:ut
```

运行集成测试：

```bash
go-task test:it
```

运行单个 E2E 用例：

```bash
go-task e2e -- --case case_ws
```

运行全部 E2E：

```bash
go-task e2e
```

运行 Go 单元测试、集成测试和全部 E2E：

```bash
go-task test
```

每个 E2E 用例会独立启动一套后端服务，服务日志写入该用例目录，例如 `data/e2e/case_ws/logs/server.log`，用例结束后会关闭服务。

修改代码并新增行为时，应先补充覆盖需求的 E2E 用例，确认新增用例失败后再实现，最后运行单用例和全量 E2E。

## 常用环境变量

- `AGENTHUB_PORT`：Web 服务监听端口，默认 `17375`。
- `AGENTHUB_TOKEN`：前端访问 token，默认空。
- `AGENTHUB_DATA`：后端 JSON 状态目录，默认 `~/.agenthub/data`。
- `AGENTHUB_LOG_NO_COLOR`：禁用日志颜色。
- `MOCK_AGENT`：启用 Mock Claude Code 和 Mock Codex 的内置 profile。
- `AGENTHUB_MOCK_CLAUDE_COMMAND`：E2E 覆盖 Mock Claude Code 启动命令。
- `AGENTHUB_MOCK_CODEX_COMMAND`：E2E 覆盖 Mock Codex 启动命令。

## 常用目录

- `cmd/web`：Web 后端服务。
- `fe`：前端应用。
- `scripts/go-scripts`：go-task 调用的 Go 脚本。
- `scripts/tasks`：Taskfile 任务拆分。
- `data`：本地构建和测试产物。
